# GitHub Actions PR Checks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. The user selected implementation in this chat. Use one independent whole-branch reviewer at the end.

**Goal:** Add working PR validation and a fresh, fully mocked infrastructure deployment to GitHub Actions, with regression tests for the introduced behavior.

**Architecture:** Two ephemeral Ubuntu jobs validate a public checkout and deploy the real infrastructure. A local read-only smart HTTP Git server supplies independent infrastructure and encrypted-secret repositories; a fresh K3s installation runs Flux, Helm controllers, test TLS, and the demo application.

**Tech Stack:** GitHub Actions, Ubuntu 24.04, Bash, Python 3.12, unittest, PyYAML 6.0.3, Git smart HTTP, age, SOPS, Flux, K3s, kubectl, Gitleaks.

**Spec:** `docs/superpowers/specs/2026-10-12-pr-ci-design.md`

## Global Constraints

- Keep `K3S_VERSION=v1.35.9+k3s1`, `FLUX_VERSION=v2.9.6`, and `SOPS_VERSION=v3.13.3`.
- Use GitHub-hosted `ubuntu-24.04`, `contents: read`, SHA-pinned Actions, `persist-credentials: false`, `submodules: false`, and full public checkout history.
- Trigger on `pull_request`, pushes to `master`, and manual dispatch. Run both `Validate` and `Deployment` for all PRs; deployment depends on validation.
- Never use private module contents, ambient production keys, cloud credentials, repository secrets, production kubeconfigs, or `pull_request_target`.
- New behavior gets regression tests. Future test coverage is a review requirement; do not implement a test-file-change gate.
- Use `demo.infra.test`, the existing isolated fixtures, production namespaces/controllers/demo, and a disposable age identity.
- Refuse existing K3s installations/configuration; require `--disposable` acknowledgement. Swap disabling belongs only in the ephemeral Actions job.
- Credential files and temporary directories use modes 0600 and 0700. Apply secret bytes through stdin and suppress their subprocess output.
- Upload only allowlisted readiness diagnostics and a report; never raw logs, Secret YAML, identities, environment dumps, or kubeconfigs.
- Do not change branch protection or merge automatically. Create a reviewable PR and confirm its actual Actions deployment passes.

## Review Focus

- A tracked Gitlink, unsafe export path, or ambient SOPS configuration cannot bring private files into a fixture repository.
- Authentication for one mock repository cannot read the other; neither credential can push.
- Any failed readiness, probe, HTTPS, or production-resource absence assertion fails deployment rather than producing a passing report.
- Cancellation stops the mock server and removes temporary credentials; report serialization contains only an allowlisted schema.
- Fork PR execution gets no persistent checkout credentials or private module access and tests the merge checkout.

## Task 1: Authenticated local Git and disposable SOPS fixtures

**Files:** Create `tests/ci/__init__.py`, `tests/ci/git_server.py`, `tests/ci/fixtures.py`, `tests/test_ci_git_server.py`, and `tests/test_ci_fixtures.py`.

**Interfaces:**

- `GitServer(repositories: dict[str, tuple[Path, str, str]], host: str = '127.0.0.1', port: int = 0)` is a context manager. It exposes `base_url: str`, serves each mapped bare repository with its own username/password, and shuts down/join its HTTP thread on exit.
- `clean_env() -> dict[str, str]` removes inherited SOPS/age and Git credential/config overrides and disables global/system Git config and interactive credential prompts.
- `FixtureSet.create(source: Path, work: Path, base_url: str) -> FixtureSet` exports public tracked blobs, patches the isolated private source, creates bare repositories, generates age credentials, encrypts the initial probe, and commits both fixture branches as `main`.
- `FixtureSet` exposes `repositories: dict[str, tuple[Path, str, str]]`, `identity: bytes`, `infra_url: str`, `secrets_url: str`, `infra_revision: str`, and `secrets_revision: str`.
- `FixtureSet.update_probe(value: bytes) -> str` encrypts with explicit SOPS rules, commits the changed fixture, pushes only to its local bare repository, and returns its new revision.
- `FixtureSet.bootstrap_objects() -> list[dict]` produces two Git credential Secrets, the SOPS identity Secret, the infrastructure GitRepository, and the root Flux Kustomization for `./tests/isolated`.
